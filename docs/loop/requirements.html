Rev3 Requirements

Everything this week's decisions require of the reworded skills, as checkable statements. Each carries its motivation, because the skills themselves must too. Approving this page makes it the review checklist for the rewording pass — nothing agreed in conversation has force until it's encoded here and then in the skills.

Cross-cutting — every skill

One vocabulary. The skills speak the same language as the framework: goal function (the done-signal command), goldens (regression snapshots the operator blesses), anchors (check-time expected-value producers outside the worker loop), frontier (the tasks ready to start — prerequisites done, nobody on them), lease (a worker's time-limited claim; a dead worker's lease lapses and the task returns to the frontier), proposal (a filed suggestion of new work, routed later), journal (the append-only history of every state change and its evidence), outbox (the questions waiting for the operator), bless (the operator's recorded "looks good" that graduates candidate goldens). "Oracle" appears nowhere. "Ledger" survives only as a description of the journal.
The old skill used "oracle" for two different things; the operator couldn't tell which act they were performing.
Mechanism, not instruction. Every prohibition names the mechanism that fires when it's violated — or names the residual risk when none exists.
"A written instruction is not a control" — a forbidden act happened first-try with the prohibition in the brief, twice, in two different flights.
Framework by verb. Skills reference shipped verbs (status, propose, bless, attach) and never describe machinery agents should improvise. An instruction requiring code the framework doesn't ship is a defect in one of the two.
The no-driver gap cost yesterday's flight 6,327 lines of throwaway Python and ~60 relaunches.
One decision, one owner. Every judgment the pipeline needs names who makes it — planner, judge, framework, or operator. No skill may leave an agent to infer its position in the run.
Item-058: the a2a flight didn't know who owned the handoff; the wt flight handed its stop condition to a reviewer.
Plain words at every operator surface. The jargon firewall the handoff front page already obeys extends to everything the operator reads: escalations, status output, plan pages, the stamp ask. No machinery vocabulary, no identifier that isn't defined where it appears; internal keys stay in machine-facing columns. Anyone should be able to understand what's being asked of them.
Encoded once for handoff — rev9's front page was useless to the operator it was written for — and violated since anyway: escalations surfaced as "A12" and "Q-C".
Proportional ceremony. The operator's request sets the ceremony; discipline above the request substitutes mechanism and says so; ceremony above the request is spend the operator declined.
Four of seven early feedback entries were inbound-handoff ceremony fighting the operator's actual ask.

Scaffold

The plan is a contract and must contain, in its readable sections: the anchor choice per surface (reality / spec / operator judgment) as plain-language statements the operator can judge; the demonstration list; the review severity bar; the handoff phase naming its owner; the flight's test-path globs; every operator act with its rationale; the envelope.
Every operator judgment moves to the one moment it's exercisable — plan approval. Mid-run acts asked for judgment over bytes.
The task table is machine-derivable. Per task: id, role, effort, dependencies, check. plan-import derives the graph from it; nothing is ever hand-retyped into a second file.
The hand-derivation step is where yesterday's flight lost its per-item roles — five wasted segments and two plan revisions.
The planner invokes handoff at plan time (when the skill is available), so evidence tracking and the proof surface exist from the start; the handoff phase runs production at the end.
Handoff's accumulation half belongs to whoever does the work — a flight that skips it re-derives its own evidence for hours at the end.
Pull, lease, sequential. Workers ask the framework for eligible work matching their profile; claims are leases; the framework is the sole writer of task state; v1 runs one worker at a time. One canonical cycle: lease → work → candidate commit → typed claim → framework verifies the commit → framework flips. Workers never select their own work and never flip their own state; a slice cycles while succeeding, and a failure or low context ends it.
Both parallel-clobber incidents were concurrent writers; every observed ledger lie was an agent grading itself.
Verification carries the model whole: the anchor principle; the layered goal function (mechanical core red-first from a walking skeleton, the handoff-scrutiny chain terminal); calibration on a known-good subject where one exists; the checker-breaker for high-stakes checkers; the defense ladder ending in named residual risk the operator accepts knowingly; the test-edit diff-gate; the closed verdict enum (red is not broken; killed is neither).
In an unattended run the check is the only thing between done and looks-done; every corruption of it corrupts everything downstream.
Done is three file checks: mechanical core green against the previously-blessed set; every planned demonstration has a freshness-valid candidate tagged with its verified_head; production scrutiny complete and adjudicated against the bar. Then the run stops at done-pending-bless. A refused stamp is classified: a visible defect inside the plan's own words gets one bounded remediation round; a missing or changed expectation routes to plan revision or intake — never a retry loop either way.
Agents must know they're done before presenting; readiness is a checklist, not a judgment — and no loop terminates on anyone's satisfaction.
Discovered work: do it small or file it. Workers never mutate the graph; proposals are routed at batch points by a planning context — in-envelope joins the graph, beyond-the-flight becomes an inert tasks entry, envelope-breaking escalates. The handoff's follow-ups are generated from the routed entries.
One filing verb, one routing decision, one place the operator meets each discovery.
Attending contexts stay disposable; attach = status plus unanswered outbox rows first; wrap-up feeds the handoff — one account per crossing.
A hidden attending session once re-paid 288M tokens to know nothing the store didn't.

Handoff

Two phases, named. Accumulation belongs to whoever does the work and is set up at plan time in flights; production belongs to the named owner; inbound review is production running alone.
Settled this week; the composition gap was measured at 6.5 hours of re-derivation.
Citations never replace demonstrations. Cited records excuse re-running checks — never showing the work. Every user-visible promise owes a showing a human can watch, captured at first pass and replayed or regenerated at the presented commit before the stamp ask — the operator never approves a stale capture.
The operator's confidence comes from watching it work, not from attestations.
The front page is the stamping surface. For judgment-anchored surfaces, candidate goldens are presented as the demonstrations; the operator's "looks good" accepts the handoff and graduates candidates into the blessed set, which persists as the next flight's regression base. The jargon firewall holds: no machinery vocabulary on the page — the stamp is offered in the product's own words.
One ceremony, not two; each handoff leaves the system easier to verify than it found it.
Review completion ≠ verdict. A review passes on a complete, well-formed review; findings are adjudicated against the plan-time bar and route to successor tasks. A truthful reviewer can always finish.
The review/remediation deadlock: an honest reviewer could never turn the boolean true.

Delegate

Role contracts declare write authority. Read-only roles (prober, reviewer, qa-tester, judge) are marked as such — the framework refuses to lease product-mutating work to a read-only role, and future parallelism will read this field.
A qa-tester was dispatched to do an implementer's commits; the contract said it couldn't, so three segments burned honestly failing.
Job prompts are shipped, not authored per-flight. Delegate resolves minds; the framework supplies prompt templates per job (worker roles, initial planning, proposal folding, judgment, handoff production). No flight hand-maintains its own prompt headers.
Yesterday's hand-grown segment header was stale (wrong revision stamp) within hours.
Stop bars and escalation rungs stay as written. Dispatch loops are bounded by a pre-fixed severity bar; binding escalations go effort-then-tier, once each, recorded.
Already landed; restated so the reword can't lose them.

Intake

Ambiguity blocks the plan — now with teeth. Surviving ambiguity goes back as a requirements row with default and blast radius; and downstream, a task failing on ambiguity escalates rather than retries.
Measured: cheating jumps ~20× on under-specified tasks. Intake is the cheapest defense the pipeline has.
Rows are referenced by concept name in conversation; numbered ids exist for the written record only.
Operator feedback: ids don't fit working memory.

Tasks

Tasks stands alone. The skill exists independently of scaffold — a backlog any conversation or agent can feed, useful with no flight anywhere in sight. Routed flight proposals are one inflow among many, and nothing in tasks may assume a flight exists.
A third party reading only the tasks skill must find it complete on its own terms.
Receives routed proposals as inert entries — when available and authorized, else an outbox row — each carrying provenance: which flight, which task, why it matters. No execution authority, ever.
The backlog is the operator's; agents fill it, only the operator spends it.

The ambiguities that must die

Each burned a real flight. The reworded skills are checked against this table directly: every question must have exactly this answer, stated where an agent will meet it.

QuestionOwner / answer
Who shows the operator the plan?The agent that invoked the planner — in the operator's chat, as a page.
Who owns the handoff?The owner named by the plan's handoff phase.
Who flips task state?The framework only, on its own verification.
What counts as an attempt?Typed by the framework: work / infra / diagnostic — infra never burns budget.
When does the run end?The three internal-done checks; then done-pending-bless.
What reaches the operator mid-run?Judge-gated outbox rows only: irreversible or envelope-breaking.
Who mutates the graph?Planning contexts, at batch points — never workers, never per-finding.
Who sets a worker's model and effort?Roster and plan, resolved mechanically — never the worker.

Deliberately not here

  • The software-engineering skill — the operator is writing it: leave-it-better ethos, pragmatic tradeoffs, knowing when to stop. The loop stays neutral and provides only the propose verb.
  • Framework internals — the build plan owns those; this page only constrains what the skills say about them.
