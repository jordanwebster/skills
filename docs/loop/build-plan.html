Dumb Loop Build Plan

What gets built, in what order, under what engineering discipline. Codex implements this once the design and this plan have your yes.

Shape

One small Python package, stdlib-only at runtime, living in the skills repo and installed by the existing installer. One CLI entry point (working name scaffold — rename freely). No daemon required, no external services, everything is a file, works on a laptop. Vendor knowledge exists in exactly one directory (adapters); the rest of the framework could not tell you which CLI did the work.

It walks a graph, not a queue

Your instinct is right: with depends_on on every task, the store is a dependency DAG and "the queue" is just its ready frontier — tasks whose dependencies are green, unleased, not parked or blocked. v1 is fully sequential: one worker holds a lease at a time. Concurrency was cut deliberately — even a "read-only" reviewer running beside a writer watches the worktree change underneath it, so safe parallelism needs readers on stable snapshots (a worktree at a verified commit), which is future work, not v1. The graph still earns its keep sequentially: dependency-ordered selection, honest blocking, and a frontier any status query can read.

One canonical cycle, everywhere the documents speak of work: the loop selects and leases one frontier task by the mechanical rule → a worker executes it → the worker lands a candidate product commit and files a typed claim → the runner verifies that immutable commit → the loop alone applies the flip. A worker slice repeats the cycle while it succeeds; a failure or a low context ends the slice. "Pull" means asking the loop for eligible work — never browsing the store.

Modules and their contracts

store — the graph on disk

tasks.json (current state) + journal.jsonl (append-only transitions: every flip, its evidence, its verified_head), written atomically (temp + rename), committed together to the scaffold-local repo. The framework is the only writer of state; workers file typed claims.

load() / ready(profile) -> [Task]        # the frontier, filtered by role profile
claim(task_id, holder) -> Lease           # atomic; expired leases re-queue themselves
file_claim(task_id, evidence_path)        # worker-side: "I believe this passes"
apply(transition)                         # framework-only; validates against the legal-
                                          # transition table, appends journal, fails closed

The plan document embeds a canonical machine block (JSON) from which its readable task table is rendered; plan-import reads the block, never the prose. Task fields: id, title, role profile, effort, check command, depends_on, decisions-already-made (interfaces, paths, out-of-scope), typed attempts (work / infra / diagnostic), completion + verdict (separate), evidence, verified_head, lineage (retired / revoked / superseded), schema_version.

loop — the driver

Select frontier → assemble prompt (concatenation of durable files, scoped to the task, from shipped templates flavored per role and per job: worker roles, initial planning, proposal folding, judgment, handoff production) → dispatch through an adapter → verify → apply → heartbeat. One process, single store-writer, a one-line human-readable event log (segment 25: phase-08 → claude/opus/high … flipped [39,40,41]; verify green; stalls 0 — the legibility that saved the a2a flight's babysitter and whose absence sank yesterday's).

adapters/ — the only vendor-aware code

dispatch(prompt, binding, sandbox, timeout) -> Result
  # Result: exit_class, transcript_path, last_message_path
  # claude.py, codex.py, fake.py — fake powers the whole test suite

Bindings come from the delegate roster; sandbox flags, structured-output flags, transcript capture, and secrets-hygiene filtering of retained logs live here. A new agent CLI = one new file.

verify — the firing mechanism

verify(task) -> Verdict{green | red | infra | killed | malformed, artifacts, reason}

Test edits are detected programmatically: the flight's config declares its test-path globs once at plan-import (e.g. tests/**, **/*_test.rs), and the runner intersects git diff --name-only over the task's commits with those globs — a non-empty intersection on a task whose brief lacks test scope withholds the flip for a judge; everything else proceeds untouched. Verdicts come from result artifacts, never bare exit codes; evidence is schema-validated at write time so one task's bad paperwork reddens that task and can never stop the line; only malformed (the machinery itself is broken) halts the run. Timeouts derive from observed run history, not constants.

supervise — process lifetime

run / start / drain / stop / status. The supervisor owns each worker's process group and kills by group; liveness is a heartbeat file, never ps; the lock is flock-held; drain (finish the current task, then stop) is a distinct verb from stop. The kill path lives outside anything a worker can write. start must survive the shell or chat that issued it ending, and the run must pause and resume safely across machine sleep — the invoking agent starts the run on the operator's yes and says so plainly ("started; you can close this chat"), with the lid-closed truth stated, not implied.

judge + outbox

Mechanical triggers only (retry cap, stall fingerprint, identical-error repeat, wall-clock cap) dispatch an ephemeral judge whose decision is typed — split | rebrief | rebind | park | impossible | defer-to-operator — with malformed decisions downgraded to park-and-escalate. Quota-smelling failures burn no attempts, back off, and park if persistent.

Mid-run discovered work. Workers never mutate the graph. A worker that discovers work — a refactor worth doing, a probe that should exist — has two honest moves, split by size: adjacent improvements its task's checks still pass under are done in place and noted — the ethos of when to polish and when to stop belongs to the operator's software-engineering skill, not to loop machinery. An improvement that would outgrow the task's verification or blur its diff gets filed as a proposed task (a durable record: what, why, suggested placement) and the worker moves on. That's the whole decision a worker ever makes: do it small, or file it. At batch points — a judge firing, or the frontier running empty — a fresh planning context routes what was filed, asking one question: does this serve this flight's goal? In-envelope work joins the graph; real work beyond the flight becomes an inert entry in the operator's backlog (the tasks skill, when available and authorized — else a local follow-ups list presented once at handoff, because the outbox is reserved for decisions blocking the run now); envelope-breaking work becomes an operator escalation. The handoff's follow-ups section is generated from the routed backlog entries, so nothing is bookkept twice and the operator meets each discovery exactly once. Graph mutation authority belongs to planning contexts, in batches — never to workers, never per-finding.

Reaching the operator. The outbox is the only path to you, and the judge is its gatekeeper — defer-to-operator is a decision it must argue, not a default. The standing rules keep it quiet: reversible and in-envelope → take the default, log it in the decision register, and let the handoff's front page present the high-value calls with their alternatives for your review at the end; irreversible or envelope-breaking → an outbox row in the fixed shape (blocked on X; I would do Y; here is what that would affect; veto or confirm) while the run continues on independent work. v1 makes no delivery promise — rows surface first on any attach, and the agent you answer turns your chat reply into the recorded ruling and unparks the work. What fits the plan is implementation detail and never reaches you at all.

Completed reviews route mechanically. Review tasks are ordinary planned tasks — the planner places them mid-graph after risky phases, not only at the end — and wherever one sits, the same path applies. When a review task delivers, the loop — not the reviewer — compares each finding's severity against the plan-time bar: above-bar findings become remediation tasks on the frontier, leased by an implementer briefed with the findings; one re-review round follows; findings still above the bar after that round escalate. Below-bar findings are recorded, never chased. Remediation is new work, not a failure: the review task passed by completing, the implementation task keeps its green, and nobody's retry budget is touched — feedback getting fixed is the system working, not anyone failing.

bless

The interaction, end to end: the operator reviews the handoff page and replies in chat; the attending agent runs bless only on an explicit accept and confirms it. A demonstration is invalidated when the surface it depicts changes, and every final demonstration is replayed or regenerated at the presented commit before the ask — the operator never approves a stale capture. On "changes needed", the feedback is classified: a visible defect inside the plan's own words gets one bounded remediation round (fix, re-verify, re-capture, one return of the ask); a missing or changed expectation returns to plan revision or intake. Acceptance graduates candidate goldens (tagged with the verified_head they depict) into the blessed set that persists as the next flight's regression base.

Engineering discipline

  • Our own medicine, red-first. The framework's goal function exists before any feature: a toy flight (tiny fake product, fake adapter) must run end-to-end unattended from a fresh checkout — init → plan-import → loop → induced stall → escalation → wrap. It runs red from M0 and its first green is the finish line.
  • Seeded-failure suite. Every failure class from the autopsy and the feedback log becomes a test that reproduces it against the fake adapter: stillborn launch, stale pid, lease expiry, role/phase mismatch rejected at load, a second writer refused while one holds a lease, review-verdict routing (no deadlock), out-of-scope test edit gating a flip, proposed-task folding, malformed evidence reddening one task, killed-verifier ≠ broken, infra failure burning no attempts, quota back-off, secrets left in a retained log.
  • Deterministic and testable. Injectable clock and id source; the fake adapter scripts worker behavior (including lying workers); self-test never dispatches.
  • Crash-safe by construction. Atomic writes, journal replay on start, a torn trailing journal line is dropped, interior corruption fails closed naming its position.
  • Fail closed on state, fail open on progress. Illegal transitions are rejected; a single bad task never stops the line.
  • No flight edits framework source. Yesterday's driver was edited 16 times in 14 hours; here per-flight variation is declarative config, and a flight that needs a code change files an escalation instead.
  • No speculative features. Quota reset-time logic, agent-spend budget integration, and multi-machine anything are out of v1 by decision, not omission.

Milestones, each with its check

M0 — Skeleton. Package layout, store read/write/journal, toy-flight goal function created and red.
Check: goal function executes and fails for the right reason.
M1 — Loop on fake adapter. Selection, leasing, prompt assembly, apply.
Check: toy flight goes green end-to-end unattended.
M2 — Verification runner. Restore+hash, verdict enum, malformed-reddens-task, artifact-based judgment.
Check: seeded lying-worker and bad-paperwork tests pass; the toy flight stays green.
M3 — Supervision. Heartbeat, flock, pgid kill, drain.
Check: kill the driver mid-run → relaunch resumes cleanly; stillborn-launch and stale-pid seeded tests pass.
M4 — Real adapters. claude + codex dispatch, sandboxing, transcripts, secrets hygiene.
Check: the toy flight runs green with each real CLI as the worker.
M5 — Judge, outbox, bless. Typed decisions, escalation records, review routing, graduation.
Check: induced retry-cap and ambiguity scenarios produce the right records; a completed review with above-bar findings spawns remediation and one re-review, then escalates; final demonstrations are re-captured at the presented commit; bless round-trips.

Then: the skills are reworded around the shipped framework, and one codex end-to-end review sweeps the pipeline against our principles, bounded by a stop bar fixed before dispatch.
